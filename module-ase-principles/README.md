# Module: Agentic Software Engineering Principles

A new treatment of the software engineering concepts of the course, built
around one running example, the message guard, that grows version by version.
It is under development and is not yet referenced from the course web page;
`module-software-engineering/` remains the module taught this semester.

What is here:

- `demos/running-example-message-guard/` — the running example, one snapshot
  directory per version. Versions A0 and A1 are complete; `build-history.sh`
  replays them into a tagged git history.
- `lecture-notes/` — student-facing notes, one file per lecture. Lecture 01
  (intent, specifications, realizations, and the five judgments, on A0) is
  drafted. Lectures 02 (the concept of operations: why, its format, how it
  is obtained, what is done with it) and 03 (from the concept of operations
  to requirements: EARS, the audit, traceability), both on A1, are planned
  and not yet written; A1's `tooling/` catalog is the reading that replaces
  lecture time on building the assurance tooling.
- `slides/` — PowerPoint decks. `lecture-01-intent-specifications-realizations-and-judgments.pptx`
  is generated by `build-lecture-01.py` from the two files in `assets/`
  (`uv run --with python-pptx --with pillow python build-lecture-01.py`);
  edit the script, not the deck, for changes that should survive a rebuild.
- The design that the module follows is
  `software-engineering/running-example-design.md` at the repository root; the
  vocabulary is `glossary.md`.

Instructor outlines will be added as they are written, following the
three-artifact layout of `module-software-engineering/`.

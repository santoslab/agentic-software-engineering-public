# Outline for the Neo4j lecture notes (`lecture-notes/lecture-mcp-neo4j.md`)

> Planning record, proposed 2026-11-18 for instructor approval before the notes
> are written. Follows plan Sections 5, 7 and 8 and the pilot report
> `../reports/desktop-pilot.md`. The instructor demos parts of the music
> homework live; each section below names the demo beat it accompanies and the
> captured figure that stands in for it on paper.

## Conventions

- Same shape as the adoption notes: title, a short placement section, numbered
  sections, a closing section of explained self-checks and a vocabulary table,
  then references. Plain technical prose; no slogans.
- Setup procedure and fixture loading are *referenced*, not repeated: the
  general guide `neo4j/neo4j-desktop-mcp-setup.md` and the homework's
  `SETUP.md`. The notes explain what the configuration means and what the host
  does with it; the guide says which buttons to press.
- Every quoted prompt, Cypher statement, dialog text, log line, and error text
  comes from the pilot report or its JSON captures. Model output is labeled as
  model output. Untested statements (database role on 2026.10; Windows) are
  marked.
- Figures: Claude Code screens from `slides/images/mcp-neo4j-NN-*.png`, Desktop
  screens from `neo4j/resources/desktop-NN-*.png`, diagrams from
  `slides/diagrams/*.svg`. JSON excerpts from `reports/live-desktop.json`.
- Two new diagrams are drafted with the notes and rendered with `build.sh`:
  `neo4j-write-sequence.mmd` (prompt → proposal → dialog → server → database →
  read-back) and `neo4j-write-controls.mmd` (the three controls as gates, each
  labeled with what it does not prevent). `neo4j-processes.svg`,
  `adoption-connections.svg`, `adoption-connections-basic.svg` and
  `music-graph.svg` are reused.

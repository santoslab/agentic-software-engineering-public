# Message guard, version A2

(The A1 instruction file, unchanged, followed by this paragraph.)

**Process control.** `process/rules.md` now says when the claims must hold.
Before any commit, run `tools/gate.sh`; the pre-commit hook runs it again
and refuses the commit if it fails (WF-1). A commit that changes a
specification needs an audit record for that state with no open gap
(WF-2); you cannot start the audit, so when a specification has changed,
stop and ask the developer to run `/audit-spec` before you attempt the
commit. The ledger, `reports/ledger.md`, is generated by `tools/ledger.py`
at every checkpoint; never edit it by hand, and never write a status from a
narrative or from memory (Ledger-1). Running the gate and the generator
regenerates the files under `reports/`; that is expected and needs no
approval.
